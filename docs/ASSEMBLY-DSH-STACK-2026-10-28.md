# 组装方案：把四个 DSH 插件 + 我们的记忆库拼成一个"有记忆的助手"（2026-10-28）

> 前提发现：`tencent-connect/dsh-qqbot` 的架构是 `QQ → 插件 → ctx.agents → dsh agent loop → LLM`。
> **大脑是 DSH 本身** ⇒ 我们的记忆注入/写回**只做一次**，所有 DSH 插件共享。
> 这就是"记忆库当枢纽"的落地形态：不是每家写一个适配器，而是**一个宿主 + 一个记忆服务**。

## 一、角色分工（各取所长）

| 组件 | 角色 | 长处 | 短处（谁补） |
|---|---|---|---|
| **DSH** | 宿主 / 大脑 | agent loop、工具调用、插件机制、profile 隔离 | 本身不产出人格与主动性 |
| **`dsh-qqbot`** | 入口：QQ 私聊/群聊 | 官方 Bot API，流式、富媒体、访问白名单 | 只有通道，没有记忆 |
| **我们的 memory-lib** | **记忆层（唯一真相）** | 跨入口统一、可追溯、可见性隔离、双时间轴 | 不会说话、不会主动 |
| **`c1overzz/dsh-bili-scroll`** | 感知源：B站 | 读字幕、筛内容、写日报 | 日报写完就散（→ 写进我们的 documents 层） |
| **`MerZlin/dsh-pet-indesktop`** | 表达出口：桌宠 | 主动出现、语音、音乐联动 | 没有"记得什么"（→ 读我们的记忆驱动） |
| **大肥鱼 persona/配置包** | 人格与话术 | 生活化表达、口癖、情商 | 记忆是 AstrBot 内置 embedding，**跨入口不共享** ⇒ 由我们替换 |
| `KDDKBD/DeepSeek-splash-animation` | 外观 | 开屏动画 | 与记忆无关，纯可选 |

**一句话**：大肥鱼提供**人格与主动性**，我们提供**记忆**，QQ/桌宠/B站提供**通道与感知**，DSH 把它们串起来。

## 二、数据流（只有两条主路）

```
【读】任何入口的一轮对话
  QQ / 桌宠 / 控制台
        │
        ▼
   dsh agent loop  ──(on_llm_request 等价)──▶  memory_recall_brief(query=本轮用户原话)
        │                                        │ ≤600 字、整句、带"不可信"标记
        ▼                                        ▼
     LLM  ◀────────── 注入（系统提示稳定段 + 本轮动态块）──────────┘

【写】一轮对话结束
   dsh 会话记录  ──▶  capture（适配器/侧车，幂等 event_id）──▶  evidence/conversations
                                                                  │
                                                      提炼（人工/半自动）
                                                                  ▼
                                                      curated/shared（正式记忆）
```

**关键**：这两条路**只实现一次**（在 DSH 宿主侧），所有插件共用 —— QQ 里说的话，桌宠也能用；B 站日报进库，QQ 里也能被问到。

## 三、组合后的"一天"（这才是要验的闭环）

1. 你在 **QQ 私聊**说："最近想学 Rust，但别太硬核。"
2. 写回：这句话进 `evidence`；提炼后进 `curated/shared`（偏好类）。
3. 当晚 **bili-scroll** 跑完，日报写进 `documents`（"B 站刷到 3 条 Rust 入门"）。
4. 第二天 **桌宠**主动出现："昨天你说想学 Rust，B 站有 3 条入门视频，要不要看这条？"
5. 你回 QQ 问："我上次说的学 Rust 的条件是什么？" → 它答得出"别太硬核"。
6. **重启后**再问一次 —— 仍然答得出，且**不重复推送**同一条日报。

**第 4 步和第 6 步是重点**：前者证明"跨入口共享记忆"，后者证明"重启不丢、去重有效"。

## 四、必须先解决的三件事（按顺序）

### ① 记忆必须落在"宿主层"，不能每家自己做
- QQ 插件自己不做记忆；它只负责把消息喂给 DSH agent loop；
- 我们的注入段与 capture 在 **profile 级**配置（`qqbot` profile 也要装上 `mcp-memory` + 注入 section）。

### ② 多用户隔离：QQ `openid` → 我们的 `user_id`
- 官方 Bot 里每个 QQ 用户是不同 `openid`；
- 如果所有人共用一个 `reader` 身份，**A 的私人记忆会漏给 B**；
- 方案：插件把 `openid` 映射成 principal 的 `user_id`（我们的服务支持 user 级可见性），**群聊记忆与私聊记忆分层**；
- 验收：拿两个 QQ 号，互相问对方私聊里说过的事 ⇒ **必须答不出**。

### ③ 主动行为要有闸门
- 桌宠主动说话 = 会打扰人；
- 规则：**每天最多 N 次**、只在"有新增且未推送过"时才说、可一键静音；
- 验收：连续 3 天不产生重复推送。

## 五、红线（2026-10-28 修订）

### 保留不变的三条

- ❌ **不自动刷 B 站评论**：指"自动浏览→自动发评论→自动回复别人评论"那类脚本（B 站已对批量账号限流）。`bili-scroll` 只读字幕写日报，**不在红线内**；
- ❌ **不把 `librarian-admin` 给任何公开入口**：公开入口 = 任何外部人能发消息进来的地方（QQ 群/私聊）。管理员身份能直写 curated、改角色、管密钥，一旦泄漏等于记忆库裸奔。公开入口只给 `reader` + `capture-ingest`；
- ❌ **不让"记忆里的指令"驱动工具调用**：记忆是**不可信输入**（可能来自群里任何人的一句话）。注入段必须带「不可信」标记，其中的命令式文本**只作背景，不得触发发消息/读写文件/跑命令等工具**。

### 第 4 条：从"禁止水群"改为"**只在自有测试群 + 闸门**"

> 用户已确认：不会把机器人放到未考察的地方，只在**自己能控制的测试群**跑。
> 这条对测试记忆库反而更有价值：闲聊信息密度低、话题跳跃，正好测"什么该记、什么不该记"。

允许：

- ✅ 在**自有测试群**里随机说话（不进别人的群、不做推广、不刷屏）；
- ✅ 不被 @ 也说话（`requireMention: false`，插件现成能力）；
- ✅ **选择性不理 @**（模拟真人）。

但必须满足下面 §六 的闸门与可解释性，否则测试结论不可归因。

## 六、主动行为设计（"水群"与"选择性不理"）

### 6.1 决策规则（必须可解释）

| 情况 | 行为 |
|---|---|
| 主人（用户本人 QQ）发言 | **必回** |
| 点名（含机器人名字）／明确提问（疑问句）／"记得/上次那个" | **必回** |
| 群友之间的对话（没指向它） | **可略** |
| 纯表情、无信息量短句 | **可略** |
| 其余 | **20% 概率忽略** |

**每次忽略都必须写一条日志**：

```
ignored reason=low_signal|cooldown|deferred|quiet_hours  at=…  msg_id=…
```

没有这条日志，就没法区分"它忘了记忆"还是"它选择不理"。

### 6.2 主动发言的闸门

| 闸门 | 建议值 | 理由 |
|---|---|---|
| 最小间隔 | ≥ 10 分钟 | 别像刷屏 |
| 每小时上限 | ≤ 3 条 | 人的密度 |
| 每日上限 | ≤ N 条（可配） | 防失控 |
| 静默时段 | 可配置（如 01:00–08:00） | 像人 |
| 冷却 | 刚被忽略/刚被怼后 30 分钟不发 | 减少骚扰 |
| 触发条件 | 只在"**有新增且未推送过**的内容"时主动说（如新日报、新记住的偏好） | **不能凭空编话题** |

**技术现实**：`dsh-qqbot` 的 `src/features` 只有 answer/approval/question/history，**没有定时器或主动发送**。
所以"随机水群"需要我们补一个小件（定时器 + 调它的发送通道），本仓库后续实现。

### 6.3 群聊记忆必须分层采样

闲聊是全量进库的最大风险：会把私聊里的重要记忆淹掉。

| 规则 | 建议 |
|---|---|
| 分层 | 群聊记忆与私聊记忆**分开**（群聊进独立 container / 独立 source） |
| 采样上限 | 一个群每天最多入库 N 条（超了丢弃并计数） |
| 保留期 | 群聊闲聊 7–14 天自动降冷/清理 |
| 提炼 | 群聊只提炼"关于主人的事实与偏好"，**不提炼别人的私事** |

## 七、明确不做

- ❌ 进别人的群、公开大群做这种测试（别人不知道那是 AI 实验）；
- ❌ 群发、商业推广、刷屏；
- ❌ 在群里回任何人的私人记忆（只答当轮、只用该身份可见范围）。

## 八、落地顺序（每步都能单独验收）

| 步 | 做什么 | 谁来 | 验收 |
|---|---|---|---|
| 1 | `qqbot` profile 加 memory MCP + 注入段 | 我（配置样板） | 该 profile 的 `memory_health` 通、注入段出现 |
| 2 | 你申请 QQ 机器人 AppID/Secret，扫码 | **你** | 私聊能回话 |
| 3 | 私聊说一件事 → 隔天问 | 你操作 | 答得出，且 `evidence` 里有这条 |
| 4 | 两个 QQ 号互问对方私事 | 你 | **答不出**（隔离生效） |
| 5 | 接 bili-scroll，日报写进 documents | 我（适配） | 问"上周 B 站刷到什么"能检索到 |
| 6 | 接桌宠，主动分享一条 | 我（规则）+ 你（体验） | 每天 ≤N 次、无重复 |

## 九、风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| QQ 官方 Bot 需审核/沙箱限制 | 可能只能在沙箱群测试 | 先用私聊（c2c）验证 |
| 插件版本与 DSH 版本耦合 | 升级即坏 | 固定版本，profile 隔离 |
| 记忆膨胀（QQ 闲聊全进库） | 检索变差、提炼队列堆积 | 群聊只存 @ 它的轮次；私聊可设保留期 |
| 桌宠主动打扰 | 体验崩 | N 次上限 + 静音开关 |
| 跨用户泄漏 | **事故级** | 第 4 步的隔离验收不通过就不许上线 |
